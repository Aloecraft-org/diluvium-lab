## 1. The homepage Prism grammar is missing the regex literal

**Open. Needs a decision about who does it.**

The backtick literal shipped in `5.5.1_build13` on 2026-09-06. Three
grammars describe this language, and they do not agree about it:

| grammar | repo | backtick regex | format spec |
|---|---|---|---|
| `src/notebook/highlight.js` | diluvium-lab | fixed on this branch | fixed on this branch |
| `site/static/assets/prism-diluvium.js` | diluvium | **missing** | has it |
| `editors/vscode/syntaxes/dlua.tmLanguage.json` | diluvium | has it | has it |

So the public site currently paints `` `(\d+)-(\d+)` `` as an operator,
an identifier and an operator, for a form the compiler has had for two
days. The vscode grammar already got it right, which makes this a
transcription rather than a design question: `string.regexp.dlua` in the
tmLanguage has the three rules that matter — a backtick opens, a doubled
backtick is one backtick of pattern and does not close, and the literal
may not cross a line — and Prism needs the same three as one
`insertBefore('lua', 'string')` entry.

Section 6 gives session C "the lab and the site", so this is C's work by
the plan. It is not blocked; it is out of reach. This session has
read-only access to `Aloecraft-org/diluvium`.

**What would settle it:** push access to `Aloecraft-org/diluvium` for a
session working section 6, or a hand-off to session A, who is already in
that repository. Either is fine. Leaving it is the bad option, because
the mis-colouring is on a public page.

## 2. Neither spec is committed anywhere

**Open. Needs the files, or a pointer to them.**

`diluvium-syntax-proposals.md` and `diluvium-numeric-spec.md` are named
throughout the plan — C0 is "every form in the proposals doc" — and are
in neither repository at the commits above. C0 was therefore drafted from
what section 4 names plus the language that has already shipped
(`CHANGELOG.md`, `doc/Guide.md`, and the two grammars in the table).

That is enough for the forms whose notation is written down. It is not
enough for these five, which the plan names but does not spell out, and
which are deliberately **not** drafted:

| form | named in | what is unknown |
|---|---|---|
| `@` for `self` | §4 A6 | whether `@` is a primary expression anywhere or only inside a class body |
| `<deterministic>` | §4 A4 | an attribute, but the Lab does not tokenize `<const>`/`<close>` specially either |
| lambdas `\|x\| expr` | §4 A4 | parameter list shape, and how it ends |
| destructuring | §4 A4 | the binding syntax |
| slicing via `__slice` | §4 A4 | the surface form; `__slice` is the metamethod, not the notation |

Guessing any of these buys a probe that either never fires or fires on
the wrong thing, both of which are worse than the form staying dark.

**Cost once the notation is known:** one snippet in
`SYNTAX_CANDIDATES` (`src/kernel/lua-harness.js`), one case in
`tokenize` (`src/notebook/highlight.js`), one name in `SYNTAX_FORMS`, one
test. Perhaps twenty lines a form. It does not need session A to have
landed anything first — the probe keeps it dark until they do.

**What would settle it:** the two files, a branch that has them, or a
paste.

## Also, for session A: the freeness corpus and the probe list are one list

**No decision needed here — this is a note into §3, if the owner agrees
it belongs there.**

§3.6 has session A building `test/syntax/freeness/*.lua`: one file per
new form, each of which must **fail** to parse on pristine upstream
`luac`. `SYNTAX_CANDIDATES` in `src/kernel/lua-harness.js` is that same
artifact pointed the other way — one snippet per form that parses on
Diluvium and not on stock Lua. Both exist because principle 1 makes every
new form a syntax error upstream, which is the property that makes each
list work.

Two lists with the same content and no interface between them drift, and
the drift is silent in both directions: a form A lands with a slightly
different notation leaves the Lab's probe failing forever and nothing
says so.

What the Lab probes today, for A to diff against the corpus:

```
regex       return `x`
separators  return 1_0
binary      return 0b1
optional    local a = nil local b = a?.x local c = a ?? 1
compound    local a = 1 a += 1
secure      ~function __probe() end
```

If A publishes the corpus in a shape the Lab can read — the files
themselves, or the form names beside them — the Lab reads it and this
list stops being maintained by hand. A is the authoritative side; C
should follow, not duplicate.
